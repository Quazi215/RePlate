# Domain docs

This repository uses a single-context layout:

- `GLOSSARY.md` at the repository root for domain terminology.
- `docs/adr/` for architectural decisions.

Before exploring the codebase, read the glossary and any ADRs relevant
to the area being changed. If they are absent, proceed silently.
Create them through domain-modeling only when terms or decisions
need recording.

Use the glossary's vocabulary in issues, code, tests, and proposals.
Surface conflicts with an existing ADR explicitly.
