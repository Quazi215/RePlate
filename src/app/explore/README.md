# Info and Explore frontend

The SNAP awareness infographic is the homepage at `/`. It preserves the October 2026 work-rule clock and existing official case-help links. Find your next step opens the separate `/screening` route for NYC residents who have not applied. The shared header links to Info (`/`) and Explore (`/explore`); screening also identifies its current route. The old `/prototype/snap` and `/prototype` routes redirect to `/` and `/explore`. See [original homepage content sources](../../../docs/design/snap-review.md).

The screening journey ([#14](https://github.com/Quazi215/RePlate/issues/14), [#15](https://github.com/Quazi215/RePlate/issues/15)) checks the published assistance-based shortcut and, otherwise, the 130%, 150%, or 200% monthly income guideline for SNAP household sizes 1–8. Age/disability/blindness, out-of-pocket dependent care, and earned-income answers select the verified income row. Child support actually paid to someone outside the SNAP household is subtracted once before that comparison. Questions appear one at a time with examples, validation, and explicit unknown choices. Unknown, conflicting, and unsupported circumstances produce uncertainty. Results explain the current-answer check, limited coverage, and official review; they do not approve/reject eligibility or submit an application. Review/edit recomputes the result and clears obsolete follow-ups; Start over, refresh, and leaving clear answers. Preparation and an optional ACCESS HRA application link appear only after results, with notice that information must be entered again.

Screening answers remain in component memory, never entering URLs, storage, logs, analytics, or answer-bearing requests. No accounts, identifiers, uploads, screening APIs, database, or Gemini calls are involved. [Rule sources, exact standards, effective dates, branch map, and exclusions](../../lib/screening/SOURCES.md) record the reconciliation of the City guide's stale section date with the October 1, 2026 standards. [Local journey verification](../../../docs/design/snap-screening-verification.md) covers #16; reference comparisons and observed use remain #17. Grocery planning and Gemini conversation remain deferred. No live API parity, official eligibility, or improved usability is established by automated checks alone.

The map-first Explore screen follows `REPLATE-DESIGN-DIRECTION.md` and the root `inspiration.png` reference. Run `npm run dev`, then open http://localhost:3000/explore. If native Next.js bindings are unavailable, use `npm run dev -- --webpack`. On Windows-mounted Linux workspaces, `WATCHPACK_POLLING=true` can make Webpack pick up edits reliably.

Explore is integrated with `GET /api/retailers`. Enter a five-digit NYC ZIP and an optional positive straight-line radius up to 25 miles, then select Find stores. Initial inputs and results are empty. Editing preserves the last submitted results and labels unapplied changes; submitting replaces the result set. Reset clears inputs, results, selection, and pending requests, then focuses ZIP. Walking/Bus controls and fare code are removed. Unsupported ZIPs are identified by the server’s reviewed lookup, not by a sample ZIP allowlist.

The API returns at most five nearby candidates, ordered by full-precision Haversine distance then stable ID. Cards show the same coordinates and distances as map pins; the UI discloses truncation when there are more candidates. SNAP authorization is still unverified for the dataset, so the notice and USDA locator remain visible. A small radius can produce a genuine no-results state with a Clear radius action.

Desktop has an inset search/list panel over the map. Cards and keyboard-operable numbered pins share selection. Mobile defaults to Map with a List switch; radius controls expand through a labeled button. The store list scrolls inside a bounded, keyboard-focusable results region. Selecting a map pin scrolls its card into view. Map failure provides retry and list access, independently of search. Two-finger pinch, wheel/trackpad gestures, and the +/− buttons zoom the map. Panning or zooming never changes the query. API/data/network failures show a separate search error, retry, and USDA locator fallback. Requests are cancelled on newer submissions, reset, and unmount; a request sequence prevents late responses from restoring old results. Searches time out after 15 seconds.

The client validates ZIP/radius syntax and validates the fields used to render API results. SNAP authorization, stock, prices, routes, travel time, and trip fare remain unverified or unknown. There are no accounts, saved queries, precise-location permissions, or routing calls. Directions are outside this simplified flow.

Leaflet loads separately from the list. OpenStreetMap tiles retain visible attribution and normal browser caching, without bulk/offline prefetch. The provider receives standard browser/network information and viewed tile coordinates; no home address or ZIP query is sent to the tile provider. Review production provider requirements separately.

Motion (`motion` 14.1.0, MIT) supplies 160ms summary entry/exit, a shared mobile view indicator, and card layout transitions. Reduced-motion preferences remove nonessential movement. Camera changes are immediate. The locally hosted Atkinson Hyperlegible Next font and OFL license are under `public/fonts`. Shared branding and discovery styles live in `src/app/site.module.css`; Info layout styles live in `src/app/info.module.css`. Authorization and distance limitations remain visible in production.

No produce assets have been supplied. Generic produce art is reserved for empty states and sparse brand accents; it must not stand in for retailer photos or inventory evidence. Headlines remain exploratory.

Run `npm test`, `npm run lint`, `npm run typecheck`, and `npm run build`. Optional browser verification uses `node scripts/verify-discovery.mjs` and `node scripts/verify-snap.mjs` with an existing Playwright installation. Set `REPLATE_PLAYWRIGHT_MODULE` to its absolute `index.mjs` path when it is outside the repository, plus the normal Playwright browser/library environment settings. `REPLATE_BASE_URL` and `REPLATE_SCREENSHOT_DIR` optionally select the running server and artifact directory. Browser checks intercept tile requests and use the local retailer API for an initial integration check, then deterministic mocked API responses for radius/selection, mobile views, outages/retry, malformed responses, superseded requests, and reset. External APIs are not required. Set `REPLATE_BROWSER_EXECUTABLE` to use an existing compatible Chromium browser instead of Playwright’s default browser.

The [original visual review](../../../docs/design/discovery-review.md) records the previous fixture-based UI; it is historical evidence, not verification of this API integration. Screenshots and deterministic browser checks do not establish full WCAG conformance, screen-reader compatibility, performance targets, or shopper usability.
