# Hiraku (RePlate repository)

Hiraku spreads awareness of NYC SNAP changes and links residents to official next steps. Info is the homepage at `/`; the secondary Explore feature at `/explore` provides a grocery map and ZIP/radius search. Explore calls the retailer search API with a ZIP and optional straight-line radius and displays local supermarket candidates as list cards and map pins. Current SNAP authorization remains unverified. See the [frontend guide](src/app/explore/README.md).

## Local setup

1. Install Node.js 20.9 or newer and npm.
2. Run `npm ci`.
3. For optional local Shosai guidance, copy `.env.example` to `.env.local`, set `GEMINI_API_KEY`, and keep the verified server-only `GEMINI_MODEL=gemini-3.5-flash-lite`. For spoken answers to reviewed recordings, also set `ELEVENLABS_API_KEY` and one `ELEVENLABS_VOICE_ID` (the example uses the George preset). Otherwise no provider configuration is needed.
4. Run `npm run dev -- --hostname 127.0.0.1` and open http://127.0.0.1:3000.

The backend uses a reviewed local NYC ZIP Code Tabulation Area reference and needs no routing API key or payment card. `GEMINI_API_KEY` is only for optional server-side guidance and transcription. Never prefix secret keys with `NEXT_PUBLIC_` or commit `.env.local`. Explore calls the same-origin retailer API and loads an OpenStreetMap basemap. Store coordinates and computed distances come from the validated local dataset. Info offers optional, explicitly opted-in typed or recorded Shosai guidance; Explore and screening do not call Gemini.

## Project commands

The [Slice 4 local rehearsal record and presenter checklist](docs/design/shosai-slice4-rehearsal.md) documents live guidance/transcription/speech checks and user-confirmed desktop transcription, audible matching/key-term pronunciation, and play/pause/replay. The complete spoken demo is not yet demo-ready; physical lifecycle/permission/accessibility checks, remaining speech comparisons, realistic rehearsal latency, and account settings still need confirmation.

On Info, choose Talk to Shosai, review the Google and ElevenLabs processing disclosure, and explicitly opt in. Type a fictional English NYC SNAP question, or choose Start recording to request microphone access. Stop or the 30-second limit transcribes the recording directly into the editable question box. Review or edit it, then choose Ask Shosai to request a written answer with reviewed official citations. No answer is generated by recording alone. Reviewed recorded questions also send the exact checked answer to ElevenLabs for speech; typed questions stay text-only. Automatic playback is attempted, with native play/pause controls and a Replay answer button that uses only local audio. Speech failure preserves the written answer. Cancel discards the current operation. Questions are independent; no screening inputs are transferred. Cancel, Clear, backgrounding, and leaving discard page state and stop playback; provider processing and billing cannot be retracted. Missing configuration leaves static guidance and screening available. See [source review](src/lib/guidance/SOURCES.md), [Slice 1 verification](docs/design/shosai-slice1-verification.md), [Slice 2 capture checks](docs/design/shosai-slice2-feasibility.md), and [Slice 3 verification and limits](docs/design/shosai-slice3-verification.md).

Capture requires localhost or trusted HTTPS. Desktop Chrome capture/conversion was checked; Android checks were explicitly removed from Slice 2 scope and Android/iPhone support remains unverified. Unsupported capture or denied permission leaves typed guidance available. The voice endpoint accepts only canonical mono 16 kHz, 16-bit PCM WAV up to 30 seconds, enforces the 1 MiB multipart limit using actual bytes, and bounds transcription to 15 seconds within a 45-second upload/request budget. Guidance runs separately when explicitly requested, with a 15-second guidance stage and optional 10-second speech stage within a 45-second request budget. Its JSON request accepts only `question` and optional `spoken: true`; recorded origin survives transcript edits until successful submission or clearing. The client waits at most 50 seconds per submitted request. Speech uses `eleven_flash_v2_5`, `mp3_44100_128`, and a 2 MiB streamed binary bound before base64 JSON encoding. Text waits for synthesis completion or timeout. There are no automatic retries or speech-regeneration requests. Neither the application nor the probe persists audio.

- `npm run dev` starts the local server.
- `npm run build` creates a production build.
- `npm run start` serves that build.
- `npm run lint` checks ESLint rules.
- `npm test` compiles and runs the deterministic Node test suite without adding a test dependency.
- `npm run typecheck` checks TypeScript.

## Vercel deployment setup

This repository is linked to a Vercel project, with the Next.js app at the repository root. Keep the repository root as the project root and use Vercel's detected Next.js framework and build settings. `.vercel/` is ignored so local project settings are not committed. The `/api/retailers` server function explicitly traces the local retailer CSV, ZIP reference, and borough boundary files it reads at runtime.

Create a preview deployment from the Vercel dashboard or with the [Vercel CLI](https://vercel.com/docs/cli), then confirm the build and routes before promoting a production deployment. Check the Vercel dashboard for the current deployment status.

No environment variables are required for the current app. Shosai is restricted to a local presenter-operated demo. Hosted guidance requires a separate access and abuse-control decision; do not enable its keys on public deployments. The production build command is `npm run build`; use Node.js 20.9 or newer as specified by `package.json`.

To verify a locally configured Gemini key, run `npm run gemini:check`. It loads `.env.local`, sends one short prompt to the stable `gemini-3.5-flash-lite` model, and reports only success or an error category; it never prints the key or generated text. This checks API connectivity and model access, not a user-facing Gemini feature.

The server-side ZIP/ZCTA lookup is implemented in `src/lib/location/nyc-zcta.server.ts`, with 211 reviewed internal points and distinct malformed, unsupported, and reference-data failure results. Its [reference audit and regeneration instructions](data/location/README.md) document provenance, geographic filtering, and five-borough examples. Origins are labeled approximate; they are not home addresses. Explore uses this lookup through the retailer endpoint.

The server-side retailer loader in `src/lib/retailers/retailer-snapshot.server.ts` parses and normalizes the checked-in CSV, excludes unsafe records and deterministic duplicates, and validates coordinates against local official borough polygons. The [snapshot audit](data/retailers/README.md) records 1,247 accepted candidates and three borough inconsistencies. Snapshot source/date and current SNAP authorization remain unverified and are explicit in its output and the retailer endpoint response; the shared authorization audit is still required.

Proximity ordering is implemented in `src/lib/retailers/proximity-ranking.ts`. `rankRetailersByProximity` accepts a server-resolved ZIP/ZCTA point and validated, unique-ID retailer candidates, and returns full-precision Haversine straight-line miles, distance labels, a rationale, and ranking version `straight-line-haversine-v1`. It orders by distance then stable ID in ASCII order without changing the input list. Invalid candidate coordinates are excluded and counted; invalid origin coordinates throw a location-free error. Grocery prices and unsupported travel evidence do not affect ordering. Changes to distance arithmetic or tie ordering require a new ranking version.

`GET /api/retailers?zip=10001&maxStraightLineMiles=5` composes the reviewed location reference, validated retailer snapshot, and proximity ranking. The radius is optional and must be greater than 0 and at most 25 miles. Responses include up to five candidates, provenance and authorization omissions, a truncation notice, and clear data limitations. Invalid input, unsupported ZIPs, missing data, and genuine no-results have distinct responses. The endpoint is dynamic and responses are not cached. Explore sends ZIP/radius searches on Find stores. Reset and newer submissions cancel older requests; API/network failures offer retry and the USDA locator. No travel mode is required.

The map uses Leaflet and OpenStreetMap tiles. No map API key is required. Retailer data stays in the repository snapshot; current SNAP authorization, prices, stock, and routes are unverified. Fare calculations and fictional demo stores have been removed from the Explore flow. The Gemini connectivity-check script remains available.
